# ManiacDT · Trading Journal

Журнал трейдера: Realtime Journal, Backtest, Statistics.

Можно вести несколько независимых журналов: сделки, бектест-сессии,
кастомизация и статистика относятся к выбранному журналу. В панели над
разделами нажмите **+**, чтобы создать журнал, или **•••**, чтобы переименовать
или удалить его. Первый журнал называется «Журнал 1». Старые данные
автоматически переносятся в него при первом открытии обновлённой версии.
Статический сайт — работает на любом хостинге. Аккаунты и облачное
хранение — через Supabase (бесплатный тариф).

---

## 1. Быстрый старт (без облака)

Просто загрузите папку на хостинг (Netlify / Vercel / Cloudflare Pages /
обычный хостинг с FTP). Сайт полностью работает в локальном режиме:
данные хранятся в браузере пользователя.

## 2. Включить аккаунты и облачную базу данных

1. Зарегистрируйтесь на **supabase.com** и создайте новый проект
   (Region — любой ближайший, например Frankfurt).
2. В панели проекта откройте **SQL Editor**, вставьте содержимое файла
   `supabase-setup.sql` и нажмите **Run**. Это создаст таблицу данных
   и правила доступа (каждый пользователь видит только свои данные).
3. Откройте **Project Settings → API** и скопируйте:
   - **Project URL**
   - **anon public key**
4. Вставьте их в файл `js/config.js`:

   ```js
   const CONFIG = {
     SUPABASE_URL: "https://ВАШ-ПРОЕКТ.supabase.co",
     SUPABASE_ANON_KEY: "ВАШ-ANON-КЛЮЧ"
   };
   ```

   > anon-ключ рассчитан на публикацию в браузере — доступ к данным
   > ограничивает Row Level Security из шага 2, а не секретность ключа.

5. В панели **Authentication → URL Configuration** укажите **Site URL** —
   адрес вашего сайта (например `https://journal.example.com`).
   На него ведёт ссылка из письма восстановления пароля.
6. (По желанию) **Authentication → Sign In / Up → Email**:
   - если выключить *Confirm email*, регистрация будет работать сразу,
     без письма-подтверждения;
   - тексты писем можно изменить в *Email Templates*.

После этого на сайте появится рабочая кнопка «Войти»:
регистрация по email + паролю, восстановление пароля по почте,
автоматическая синхронизация данных с облаком.

## 3. Как устроена синхронизация

- Логин пользователя — его **email** (на него же приходит сброс пароля).
- Все журналы хранятся одной записью на пользователя (JSONB).
- Запись в облако — автоматически, через ~1 секунду после изменения.
  Индикатор-точка возле email: зелёная — синхронизировано, жёлтая —
  сохранение, красная — ошибка (данные при этом сохранены локально).
- При входе с нового устройства данные подтягиваются из облака.
  Если в облаке пусто, а в браузере есть записи — сайт предложит
  перенести их в аккаунт.
- Конфликты решаются по принципу «последняя запись побеждает» —
  не редактируйте журнал одновременно с двух устройств.
- Фото сжимаются при загрузке, но учитываются в объёме базы
  (бесплатный тариф Supabase — 500 MB).

## 4. Бекапы

Меню **Данные** в шапке:
- **Бекап в Excel** — файл .xlsx с тремя листами на каждый журнал:
  Realtime, Backtest, Models (числа выгружаются как числа).
- **Экспорт JSON** — полная копия всех журналов, включая фото и настройки;
  восстанавливается через «Импорт JSON».

## 5. Темы и языки

- Кнопка «луна/солнце» — тёмная и светлая тема (по умолчанию — как в
  системе пользователя).
- Кнопка **EN/RU** — переключение языка интерфейса.
- Выбор сохраняется в браузере пользователя.

## 6. Файлы проекта

```
index.html            — разметка
styles.css            — стили, светлая и тёмная темы
js/config.js          — ключи Supabase (заполняете вы)
js/i18n.js            — словари RU/EN
js/core.js            — данные, общие компоненты, Excel/JSON-экспорт
js/cloud.js           — аккаунты и синхронизация
js/journal.js         — Realtime journal (недели + календарь)
js/backtest.js        — бектест-сессии и сводки
js/stats.js           — метрики и кривая доходности
js/main.js            — навигация, тема, язык
supabase-setup.sql    — скрипт создания базы
```
